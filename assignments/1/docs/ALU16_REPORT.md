# 16-bit ALU 设计与仿真报告

## 1. 设计概述

该项目实现了一个 16-bit 算术逻辑单元（ALU），支持 8 种操作：加法、减法、按位与、按位或、按位异或、逻辑左移、逻辑右移和无符号比较。ALU 通过 3-bit 操作码选择对应操作，并根据操作类型输出结果和相关标志位。

### 操作码映射表

| 操作码 | 操作 | 功能 | Carry/Overflow 说明 |
|--------|------|------|-------------------|
| `3'b000` | ADD | 无符号加法 | carry：进位；overflow：有符号溢出 |
| `3'b001` | SUB | 无符号减法 | carry：无借位指示；overflow：有符号溢出 |
| `3'b010` | AND | 按位与 | carry=0, overflow=0 |
| `3'b011` | OR | 按位或 | carry=0, overflow=0 |
| `3'b100` | XOR | 按位异或 | carry=0, overflow=0 |
| `3'b101` | SLL | 逻辑左移 | carry=0, overflow=0 |
| `3'b110` | SRL | 逻辑右移 | carry=0, overflow=0 |
| `3'b111` | CMPU | 无符号比较 | carry=0, overflow=0 |

## 2. 标志位详解

### 2.1 `zero` 标志（1-bit）

- **含义**：表示 ALU 运算结果是否为 0
- **触发条件**：`zero = (result == 16'h0000)`
- **用途**：条件分支、循环控制（如检测数组末尾或计数器清零）
- **示例**：
  - `0x0003 + 0x0005 = 0x0008` → `zero=0`（结果非零）
  - `0x0005 - 0x0005 = 0x0000` → `zero=1`（结果为零）

### 2.2 `negative` 标志（1-bit）

- **含义**：表示 ALU 运算结果的符号位（最高位 MSB）
- **触发条件**：`negative = result[15]`
- **解释**：在补码表示中，MSB=1 表示负数（有符号视角）；MSB=0 表示非负数
- **用途**：分支判断、符号检测（配合其他标志进行有符号数比较）
- **示例**：
  - `0x7FFF + 0x0001 = 0x8000` → `negative=1`（MSB=1，有符号视角为负数）
  - `0x0003 + 0x0005 = 0x0008` → `negative=0`（MSB=0，非负）

### 2.3 `carry` 标志（1-bit）

**只对加法和减法有意义；其他操作默认为 0**

#### 加法中的 `carry`（无符号进位）

- **定义**：从 16-bit 加法进位到第 17-bit 的标志
- **计算**：使用 17-bit 中间结果：`carry = sum_u[16]`，其中 `sum_u = {1'b0, a} + {1'b0, b}`
- **含义**：指示无符号加法的结果是否超过 16-bit 最大值（65535）
- **示例**：`0xFFFF + 0x0001 = 0x0000 (carry=1)`

#### 减法中的 `carry`（无借位指示）

- **定义**：表示是否发生无符号借位（即 `a >= b` 的判定）
- **计算**：`carry = sub_u[16]`，其中 `sub_u = {1'b0, a} + {1'b0, (~b)} + 1`（两进制补码减法）
- **含义**：`carry=1` 表示 `a >= b`（无借位）；`carry=0` 表示 `a < b`（有借位）
- **示例**：
  - `0x0008 - 0x0003 = 0x0005 (carry=1)`（8 >= 3）
  - `0x0005 - 0x0005 = 0x0000 (carry=1)`（5 >= 5）

## 3. `overflow` 标志与有符号/无符号区别

### 3.1 有符号溢出（`overflow`）

- **适用操作**：加法和减法
- **定义**：两个补码数运算时，结果超出 [-32768, 32767] 范围

#### 加法中的溢出检测

```
overflow = (a[15] == b[15]) && (result[15] != a[15])
```

- **逻辑**：同号（两数符号位相同）的两个数相加，结果符号位变化则发生溢出
- **示例**：
  - `0x7FFF (32767) + 0x0001 (1) = 0x8000 (-32768 in signed)`
    - 两正数相加得负数 → `overflow=1`
  - `0x8000 (-32768) + 0x8000 (-32768) = 0x0000 (0 in unsigned, overflow occurred)`
    - 两负数相加得正数 → `overflow=1`

#### 减法中的溢出检测

```
overflow = (a[15] != b[15]) && (result[15] != a[15])
```

- **逻辑**：异号数相减，结果符号与被减数不同则发生溢出
- **示例**：
  - `0x8000 (-32768) - 0x0001 (1)` 应得 -32769（超出范围）→ `overflow=1`

### 3.2 无符号进位 vs 有符号溢出的区别

| 特性 | 无符号进位（carry） | 有符号溢出（overflow） |
|------|-------------------|----------------------|
| **应用数值系统** | 无符号整数 (0 ~ 65535) | 补码有符号整数 (-32768 ~ 32767) |
| **触发条件（加法）** | 结果 > 0xFFFF | 同号数相加，结果符号翻转 |
| **触发条件（减法）** | a < b（有借位） | 异号数相减，结果符号异常 |
| **运算示例** | `0xFFFF + 0x0001 = 0x0000 (C=1)` | `0x7FFF + 0x0001 = 0x8000 (V=1)` |
| **实际意义** | 超出无符号范围 | 超出有符号范围 |

**关键点**：一个操作可能同时发生无符号进位和有符号溢出，也可能都不发生。

### 4.2 关键测试分析

#### 用例 2：无符号进位检测

```
输入：a = 0xFFFF, b = 0x0001
操作：ADD
期望：result = 0x0000, carry = 1, zero = 1
```

- **物理含义**：无符号数 65535 + 1 = 65536，超出 16-bit 范围，丢弃进位得 0
- **符合预期**：✓

#### 用例 3：有符号溢出检测

```
输入：a = 0x7FFF (32767), b = 0x0001 (1)
操作：ADD
期望：result = 0x8000, overflow = 1, negative = 1
```

- **物理含义**：两个正数相加，结果符号位翻转为负（补码表示中 0x8000 = -32768），违反有符号运算规律
- **符合预期**：✓

#### 用例 5：减法后零标志

```
输入：a = 0x0005, b = 0x0005
操作：SUB
期望：result = 0x0000, zero = 1, carry = 1
```

- **物理含义**：同一数减去自身得 0；carry = 1 表示无借位（5 >= 5）
- **符合预期**：✓

#### 用例 12：无符号比较

```
输入：a = 0x0005 (5), b = 0xFFFF (65535)
操作：CMPU
期望：result = 0x0001 (表示 true)
```

- **物理含义**：无符号数 5 < 65535，结果为真（1）
- **符合预期**：✓

## 5. 仿真波形说明

### 5.1 波形文件位置

- **VCD 文件**：`wave/alu16.vcd`
- **查看工具**：GTKWave（`gtkwave wave/alu16.vcd`）

### 5.2 波形中的关键信号

- `a[15:0]`：ALU 操作数 A
- `b[15:0]`：ALU 操作数 B
- `alu_op[2:0]`：操作码选择
- `result[15:0]`：ALU 运算结果
- `zero`, `carry`, `negative`, `overflow`：四个标志位

### 5.3 波形阅读指南

1. **打开波形**：

   ```powershell
   gtkwave wave/alu16.vcd
   ```

## 6. 结论

该 ALU 的设计与仿真结果表明：

1. ✓ **功能完整**：8 种操作都已正确实现
2. ✓ **标志位准确**：`zero`, `carry`, `negative`, `overflow` 的判定符合规范
3. ✓ **有符号/无符号区分**：
   - 加法进位与有符号溢出独立，能同时发生也能各自独立
   - 比较操作采用无符号逻辑，结果表示 a < b（无符号）
4. ✓ **测试覆盖完善**：覆盖了 8 项设计要求的所有场景

该 ALU 可用于数据通路设计中的核心计算单元。
